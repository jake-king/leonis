# P1 — SDL3 window → wgpu surface

Verdict: **pass on Linux, macOS and Windows, 2026-11-20** (desktop half of P1). Real GPUs on macOS and
Windows are not covered: CI has a paravirtual Metal device and WARP. Mobile is P5.

Probe: `probes/p1-sdl3-wgpu` — sdl3 0.22.1 (feature `raw-window-handle`) over system SDL3 3.4.18,
wgpu 30.0.2. It opens a 640x400 window, makes a surface from SDL's raw handles, clears it to
(0, 0.5, 1.0) for N frames, resizes to 800x500 at frame 60, then clears an offscreen texture and reads
one pixel back. Exit 0 pass, 1 fail, 2 could not run.

Machine: Arch Linux, KDE Plasma Wayland session (Xwayland for X11), NVIDIA GeForce RTX 5060 Ti, Vulkan.

The pixel check reads an offscreen texture, so it proves the device renders, not that the window
shows it. The window was checked separately: screenshots taken with `spectacle -b -n -a` while the
probe ran (`p1/p1-wayland.png`, `p1/p1-x11.png`) show the "leonis P1" window filled with RGB
(0, 188, 255) at two sampled points in each — the clear colour after sRGB encoding.

## Findings

- **A display handle is required.** `SurfaceTargetUnsafe::from_window` (window handle only) fails on
  both drivers in wgpu 30: "No `DisplayHandle` is available". `from_display_and_window(&window,
  &window)` works; SDL's window provides both handles.
- **The default present mode differs per driver.** `get_default_config` chose **Mailbox** on Wayland
  (180 frames in 52 ms: no vsync wait) and **Fifo** on X11 (2,846 ms: 60 Hz). leonis must pick its
  present mode explicitly and pace frames with its own clock, not inherit the driver default.
- Resize works: `PixelSizeChanged` arrives and reconfiguring the surface gives 800x500 on both drivers.
- `xkbcommon: couldn't find a Compose file for locale ""` is printed on Wayland when no locale is set
  in the environment. Harmless here; relevant to P3 (IME/compose) later.

## Use-after-free found on lavapipe (fixed)

Run under Xvfb with lavapipe (`VK_DRIVER_FILES=.../lvp_icd.json`, the setup Linux CI uses), the probe
printed `result=pass` and then aborted at exit: `double free or corruption (!prev)`, exit 134. Cause:
`let mut window = window;` re-bound the window *after* the surface was created. The new binding is a
later local, so Rust dropped it before the surface: the SDL window was destroyed while the wgpu surface
still pointed at it — the opposite of what the SAFETY comment claimed. The NVIDIA driver tolerated it;
lavapipe did not. Fixed by declaring the window `mut` once; after the fix, 3 of 3 lavapipe runs exit 0
and the planted control still exits 1.

Lessons for leonis: the surface/window lifetime must be enforced by the type system (the surface owns
or borrows the window), not by a comment about declaration order; and a pass line is not a verdict —
the exit status is (CI checks it).

lavapipe run (Xvfb, after the fix):
```
p1 result=pass driver=x11 backend=Vulkan adapter="llvmpipe (LLVM 23.1.4, 256 bits)" device_type=Cpu format=Bgra8UnormSrgb present_mode=Immediate size=800x500 frames=180 presented=180 skipped=0 reconfigures=2 pixel=[255, 188, 0, 255] expected=[255, 188, 0, 255] ms=96
exit=0
```
A third default present mode: **Immediate** on lavapipe/Xvfb.

## CI

`.github/workflows/probes.yml` runs P1 and its control on ubuntu-24.04 (Xvfb + lavapipe), macos-15 and
windows-2025, with SDL3 built from source and linked statically (`--features vendored`; checked locally:
no dynamic libSDL3 in the binary, both drivers pass).

First run (44767887737): Linux and Windows passed; **macOS failed**: every frame returned
`Occluded` — the runner treats a new window as not visible — and the probe treated that as an error.
Fix (62ace91): raise the window after creating it, skip occluded frames, and report "could not run"
(exit 2) if nothing was ever presented. Run 44768594584 at 62ace91, all three green:

```

p1 (ubuntu-24.04) p1 result=pass driver=x11 backend=Vulkan adapter="llvmpipe (LLVM 20.1.2, 256 bits)" device_type=Cpu format=Bgra8UnormSrgb present_mode=Immediate size=800x500 frames=180 presented=180 skipped=0 occluded=0 reconfigures=2 pixel=[255, 188, 0, 255] expected=[255, 188, 0, 255] ms=153
```

Findings from CI:
- **Occlusion is a normal state, not an error.** leonis's frame loop must treat `Occluded` like a
  suspended app: stop drawing, keep state, resume when visible (the same path mobile needs).
- **Default present modes so far:** Mailbox (Wayland/NVIDIA, Windows/WARP), Fifo (X11/NVIDIA,
  macOS/Metal), Immediate (lavapipe). Four platforms, three defaults — confirms leonis must choose.

## Not proven
- Real GPUs on macOS and Windows (CI has a paravirtual Metal device and WARP only).
- The GL backend and the instance's display handle for GLES on Wayland: not exercised (Vulkan only).
