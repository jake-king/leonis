# P1 — SDL3 window → wgpu surface

Verdict: **partial — pass on Linux (Wayland + X11), 2026-11-20.** macOS and Windows not yet run
(they need runners or machines; see M0-PLAN).

Probe: `probes/p1-sdl3-wgpu` — sdl3 0.22.1 (feature `raw-window-handle`) over system SDL3 3.4.18,
wgpu 30.0.2. It opens a 640x400 window, makes a surface from SDL's raw handles, clears it to
(0, 0.5, 1.0) for N frames, resizes to 800x500 at frame 60, then clears an offscreen texture and reads
one pixel back. Exit 0 pass, 1 fail, 2 could not run.

Machine: Arch Linux, KDE Plasma Wayland session (Xwayland for X11), NVIDIA GeForce RTX 5060 Ti, Vulkan.

The pixel check reads an offscreen texture, so it proves the device renders, not that the window
shows it. The window was checked separately: screenshots taken with `spectacle -b -n -a` while the
probe ran (`p1/p1-wayland.png`, `p1/p1-x11.png`) show the "leonis P1" window filled with RGB
(0, 188, 255) at two sampled points in each — the clear colour after sRGB encoding.

## Findings

- **A display handle is required.** `SurfaceTargetUnsafe::from_window` (window handle only) fails on
  both drivers in wgpu 30: "No `DisplayHandle` is available". `from_display_and_window(&window,
  &window)` works; SDL's window provides both handles.
- **The default present mode differs per driver.** `get_default_config` chose **Mailbox** on Wayland
  (180 frames in 52 ms: no vsync wait) and **Fifo** on X11 (2,846 ms: 60 Hz). leonis must pick its
  present mode explicitly and pace frames with its own clock, not inherit the driver default.
- Resize works: `PixelSizeChanged` arrives and reconfiguring the surface gives 800x500 on both drivers.
- `xkbcommon: couldn't find a Compose file for locale ""` is printed on Wayland when no locale is set
  in the environment. Harmless here; relevant to P3 (IME/compose) later.

## Not proven
- macOS (Metal) and Windows (DX12/Vulkan): not run.
- The GL backend and the instance's display handle for GLES on Wayland: not exercised (Vulkan only).
